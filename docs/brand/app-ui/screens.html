Aero app UI · step 1 · screens 1 to 9, 11 to 13

Every screen, side by side.

For each screen: two or three approaches taken from the round 5 directions (A Studio, B Colour, C Story, D Replay), in the agreed brand, with the states below. Everything is built from the components, with Kestrel Studio as example data.

Labels: Today works in Aero now (redesigned). Proposed needs new work. The tester flow (screen 10) is designed separately. Switch palette and layout at the top right; "Large" shows one approach per row.

01

Shell

Sidebar or top bar, studio switcher, nav (Home, Sites, Tests; Review lives inside a test), plan usage, account.

Pick A. The sidebar has room for recent tests with a quiet "2 new", and usage that matches every other page. C's rail plus a sessions column is used inside a session, where you move between testers. No colour in the nav.

States

Proposed

  • Studios and the switcher (today one account is one person). Without them, the top of the sidebar is the account menu.
  • "2 new" counts on Tests: needs a seen-at time per test.

Copy

  • Nav: Home, Sites, Tests. Review is a tab inside a test, so the three areas read Publish (Sites), Test, Review without three more nav items.
  • Usage line is the same everywhere: "2 of 3 sessions kept".

Engineer check

  • Shell paints from the auth cache, then the three profile reads run together (B1).
  • Phone: tab bar Home, Sites, Tests, Account. The studio switcher moves into Account.
02

Home

What's new across everything, real tests and sites first, drafts folded. No friction points from random projects on Home.

Pick A, with C's progress line as a later option. A answers "is anything new" in one list, then shows tests and sites like today but honest. B is the clearest about the three areas, but it splits one prototype across three columns. C groups by prototype, which suits people with a few projects.

States

Proposed

  • The feed needs events (session finished, review ready, site expiring) and a seen-at time.
  • Draft rule (B7): save a draft only after real input; clear empty ones after 7 days.
  • Clicking a test opens Sessions or Review when they have content, not Setup (B6).

Copy

  • Greeting uses the first name only. No exclamation marks.
  • "Review ready for Pocket" not "Insights ready": Review is the area name.
  • Expiry: "goes offline in 2 days", with "Keep it live" (opens plans).

Engineer check

  • No friction quotes on Home: they belong to a test. The feed only says something happened.
  • Drafts count in the Unfinished row, never in Live (B8).
  • Counts load with their lists; no "0" before the read lands (B2).
03

Create

Three ways in (Figma link, HTML or zip, one prompt to Claude or ChatGPT), plus "Test an existing site". Only save a draft once there is real input.

Pick A. All three ways are visible and equal, the prompt is ready to copy, and the right column answers "what happens next". C is the strongest for first-time users arriving from the website ("One prompt and it's live"), so it can be the first-run version of the same page.

States

Proposed

  • Draft saved only after the prompt is copied, a link pasted or files dropped (B7).
  • "Now test it" step after publishing; today the flow ends on the site page.
  • Testing any outside link (not only Aero sites) needs checking: today a test points at an Aero site or a Figma link.

Copy

  • "One prompt" not "Build with AI". AI named only on the way in: "Claude or ChatGPT publishes it for you".
  • Errors name the file and the fix.

Engineer check

  • The prompt carries a one-time key tied to this draft; copying it is the moment the draft is saved.
  • The waiting page listens for the deploy; closing it is fine, the site still appears under Sites.
  • Address is checked as you type; taken names suggest pocket-2.
04

Site detail

URL and status (Live, or offline on Free after 7 days with a countdown), versions and roll back, settings (address, password, favicon, badge, domain), and "Run a test on this site".

Pick A. Tabs match today's code (Overview, Versions, Settings, Domain, Analytics), so it is a redesign, not a rebuild. The header always shows status and the days left on Free. "Run a test on this site" is the one glass button. B is a good single page for phones.

States

Proposed

  • Expiry state and countdown on Free (B13): status line, Overview card, site cards, Home feed.
  • "Run a test on this site" (today only the other way round).
  • Rename the Figma "Prototype" tab to "Source".

Copy

  • "Offline in 5 days on Free", never "expires". "Keep it live from $3".
  • Gated settings name the plan: "Basic", "Solo".

Engineer check

  • Days left come from the site's publish date and plan; same number on every surface.
  • Roll back reuses the version pointer; tests stay pinned to their own version.
  • Skeleton header while the site loads, not null (AeroSiteDetail B1).
05

Test setup

Tasks (optional), welcome and thank-you messages, what testers will be asked for. Variation: no tasks ("Explore freely").

Pick A. Same fields as today (tasks, welcome, thank you, screen, voice, difficulty rating, pinned version) in plain words, with a preview of the tester's first screen beside it. B's storyboard is clearer about order but cramped for longer tasks.

States

Proposed

  • Tester preview panel.
  • "Duplicate test".
  • Session target is removed from Setup: the plan limit already sets it (B14).

Copy

  • "What testers try", not "Goals". "Ask how hard each task was", not "Difficulty rating".
  • Explore freely prompt is fixed and shown, so the owner knows what testers read.

Engineer check

  • Explore freely = zero tasks; the tester sees no "0 tasks" line (B15).
  • Voice off disables transcript, summary and review; say so next to the toggle.
  • Changing tasks after sessions keeps old sessions' task list on each session.
06

Share

One link, copy, QR code, "Open as a tester" preview, a plain line on what is recorded. After creating a test, land here with the link ready.

Pick A, with B's "message you can send" below it. One link only (today the header and the Share tab show two different-looking URLs). The test wash makes the glass buttons pick up a little colour.

States

Proposed

  • Land on Share after creating a test, link copied (today: Setup).
  • QR code and "Open as a tester" (preview without saving a session).
  • What happens to sessions over the Free limit needs a decision: block, or record and hide.

Copy

  • "Send it to 3 to 5 people" is advice, not a limit.
  • "No camera, no mouse movements" is true and reassuring.
  • No "About N minutes": sessions have no set length.

Engineer check

  • One canonical link format everywhere (B: header vs Share mismatch).
  • "Open as a tester" must not count as a session or use the allowance.
  • Header "Export" removed; it only copied the link (B10).
07

Sessions list

Consistent numbering (oldest is 1), and status: recording, processing ("Transcript arriving, usually about a minute"), ready, no audio.

Pick A. A table scans fastest once there are more than a few sessions, and the first line in their words helps you choose which to open. B's cards suit the first two or three sessions and the marketing kit.

States

Proposed

  • Stable session numbers stored at start, oldest is 1 (B11).
  • "No audio" status when the mic was denied or off (B16).
  • Filters: Ready, With friction.

Copy

  • "Tester B" when no name was given, the same in the row and the session page.
  • "Ended early" for an abandoned tab, with when it closed.

Engineer check

  • Status order: Recording now, Transcript arriving, Ready, No audio, Ended early. One per row.
  • Recording now comes from the live session doc; it flips without a refresh.
08

Session view (Review)

The recording at the top, inline. The transcript with word-by-word highlight as the audio plays; click a line to jump. Summary, priorities and friction points quoted in their words, each jumping to its moment. No moving cursor today.

Pick A, with B's calm reading type. A keeps the recording first (watching is the core value) with everything that came out of it beside it. B is the calmest for reading (Duane liked C's "11:40" view): offer it as a "Read" view toggle. C works best for long sessions and moving between testers. Press play on any of them: words follow the audio. D is A once clicks are recorded (see the cursor research): proposed, shown beside today's true version.

States

Proposed

  • Inline player on the session page (today a separate route outside the shell).
  • Word-by-word highlight using the stored word timings (AssemblyAI returns them; they are saved on the session).
  • Friction points and priorities jump to their moment: needs a time per item, matched from the quote.
  • D: cursor and click ripples for HTML sites (overlay track saved as one JSON file per session); misclicks and a click path for Figma (Embed API, needs a Figma OAuth client id).

Copy

  • One source line: transcript from their voice after the session; summary and friction points written from it; quotes are exact.
  • "Friction points" not "AI insights". Severity as Low, Medium, High.

Engineer check

  • No cursor in A, B or C: tab recordings have none. D draws one only from a saved click track.
  • During processing nothing animates as typing; lines appear together when ready.
  • The project-level rail ("No sentiment yet") is removed from this page (B12).
09

Review across sessions

Themes, what to fix first, where testers disagreed. "Based on 3 of 3 sessions". With fewer than 2 sessions, show each session's top issues instead of a dead end.

Pick A. It leads with the decision (what to fix first, in their words, with the moments to play), then themes and disagreements. B, the calm written version from C, is the "Download summary" output and the email when a review is ready.

States

Proposed

  • Run the review on the server after each analysed session, not when the tab opens (B3, B5).
  • Fix the renderer's field names (avg_severity, topic, viewpoints) and add an error boundary (B4).
  • "Download summary" replaces the header's Export (B10).

Copy

  • "Review" is the tab; "What to fix first" is the lead. Never "AI insights".
  • Contradictions read as "Where they disagreed".

Engineer check

  • Themes need 2 or more analysed sessions; the count is shown, not hidden.
  • Sentiment card removed: it read a field never written (B3d).
  • Every quote links to session + time.
11

Plans and usage

Usage that matches everywhere ("2 of 3 sessions kept"), expiry warnings, and the upgrade modal from real moments.

All three, at different moments. A is the one place for plans. B opens from a real moment (a site about to go offline) and suggests one plan. C sits where the limit bites. Same meter, same words, same numbers on every surface.

States

Proposed

  • Moment modals: site expiring, last session slot, gated setting.
  • Stored usage counter instead of reading every project (Account B14).
  • Monthly allowance is planned, not live: never write "a month" after a session count.

Copy

  • Plan lines only from PRICING-FACTS. Trial: "7-day free trial, cancel any time".
  • "See plans from $3" as the soft link everywhere.

Engineer check

  • Usage meter reads one counter used by sidebar, Sessions, Share and this page.
  • Regional prices at checkout; the app shows USD with a line saying so.
12

Guidance

Short, honest explainers inside the app: how transcription works, how summaries and friction points are made, what testers see. Empty states that teach.

Both. A puts a short guide where the question comes up (beside Sessions, under the share link, in the session source line). B is the "How it works" panel behind the book icon, which is also the seed of the SEO content pages.

States

Proposed

  • Guide content lives as data (one file), shown in the app and on aeroapp.ai/guides.
  • Each guide remembers it was closed, per person.

Copy

  • Name AI only on the way out: "written from the transcript by a language model". Never "AI-powered".
  • Say what isn't recorded too: no camera, no mouse.

Engineer check

  • Empty states never show while data is loading.
  • First-run Tests suggests the newest live site by name.
