Tasks the tester can’t miss.

The user test said the task bubble looks like a notification, the permission step doesn’t say what starts the test, and stopping the share ends as “abandoned”. This board lines up every tester design we have, shows three places for the tasks, and designs the permission card, stop-sharing and page count. All names and tasks are made up (Example). Nothing here is built.

Summary

The short version.

Pick: A, a task bar across the topRecommended
  • It sits in the page, above the site, so it can’t read as a notification. It keeps the full width, so a responsive site shows its real layout.
  • One row: step badge, the task, Done and Couldn’t do it. After Done: an optional rating and a Next task button the tester presses. No hard stop.
  • The Recording pill is its own glass pill at the top centre, as on the website demo. Buttons are the V3 caustic glass buttons.
Also decided hereProposed
  • One card, one button: Start test. It says what is recorded and who sees it. “Share tab” goes.
  • Stopping the share asks “Are you finished?” and never ends as abandoned.
  • Page count: HTML sites can show the page name and arrows now. Figma prototypes can’t show “1 of 2” until the Embed API work; until then Figma’s own controls come back.
  • Your question on #302: the ⋯ is the panel menu (Move panel, Mute, Restart, End test). The line is Minimise, which folds the panel to a small pill. Under A both go: the bar doesn’t move or hide, and the menu keeps three items.

02

Three places for the tasks

Each has the separate Recording pill and the V3 glass buttons. The pill’s glass shows over the site’s own colours.

A. Task bar across the topRecommended
Full width, inside the page above the site. Louder because of its place, size and the blue step badge, not because it floats. Costs about 90px of height.
B. Docked side panelOption
Very clear, and shows what comes next. But it takes 320px of width, so a 1280px site is tested at 960px and may flip to its tablet layout.
C. Today’s floating panel, louderWeakest
Cheapest to build. Still a card over the prototype, which is what the participant ignored, and it hides part of the page in every recording.

Task, rating, no tasks, long text, end early, thank-you, phone and several pages. B and C are in the table at the end of this section.

Done pressed: optional rating, then Next task

The tester decides when to move on. Pressing a rating also moves on. If the owner turned ratings off, Done moves on at once and shows “Task 2 saved. Undo” for a few seconds.

After moving on: Undo

A chatty tester who pressed Done too early can take it back.

Long title and description

The title keeps two lines, the description one, and Show all opens the rest in a drop-down over the page. The bar never grows, so the site doesn’t jump.

Last task done

The bar becomes the finish step. It stays recording while they say what they think.

The permission card

Today’s screen and the new one, the copy, and what Chrome shows next.

Today: two rows, two buttonsToday
New: one card, one buttonRecommended
Copy

Heading Press Start to begin.

Intro Mia would like to hear you try Pocket. This is what gets recorded.

Rows Your voice: So Mia hears what you think. Talk as you go. / This tab, as a video: Only this tab. Not your face, your other tabs or the rest of your screen. / Who sees it: Mia Chen at Kestrel Studio. It’s transcribed and summarised for Mia, and nobody else gets it.

What happens Chrome asks to let this page see this tab, then to use your microphone. Choose Allow each time. Recording starts after the last one. To finish, press Finish at the top of the page. If you press Chrome’s Stop sharing, we’ll ask if you’re done.

Button Start test. Under it You can stop at any time.

Two-tab fallback The row says “Record the Pocket tab” and the button “Choose the Pocket tab”, never “Share tab”. Chrome’s own words stay Chrome’s.

  • Why “Share tab” went: the participant read it as sharing a link. Chrome’s own dialog uses “share”, so the card explains it before Chrome asks.
  • One button for both kinds of test: the HTML flow already starts the tab share and the mic from one press. The same should work for Figma tests. Ask for the tab first (it needs the click), then the mic. To check in Chrome, Safari and Firefox before building. If a browser refuses, that browser falls back to two buttons.
06

Stopping the share

The participant stopped the share the way people do in Zoom, missed Finish, and the session read “abandoned”. “Abandoned” is written by a clean-up job for sessions whose tab died, not by this.

  • Behaviour: when the video track ends, show the card. “Yes, I’m done” runs the same finish as the Finish button (thank-you, upload). “No, keep recording” asks Chrome to share again and a second video file joins the session; if they close the card, voice-only continues with the pill saying so.
  • Today in code: HTML tests finish at once with no question (UTHtmlController). Figma tests drop the video and carry on silently (UserTestingTester).
  • Closing the page with the card open: a session that has saved recording should show as Incomplete, not Abandoned. That is a change to the clean-up function, flagged as decision 6.
  • The start card now tells them about this before it happens.

09

Decisions for you

Numbered, with a recommendation.

  1. LayoutA, the top bar. B only if you want the full task list always visible. C is not recommended.
  2. Recording pillHang it just under the bar at the top centre (as on the demo), or put it inside the bar and lose the separate-pill look? I recommend under the bar.
  3. Done always onDrop the Figma rule that disables Done until the tester has used the prototype. The tester decides.
  4. RatingInline and optional next to Next task, with Undo, instead of a modal after every task.
  5. One permission buttonOne card and one Start test button for Figma and HTML tests, after we check it in Chrome, Safari and Firefox.
  6. Stopping the shareAsk “Are you finished?”. And change the clean-up job so a session with saved recording is Incomplete, not Abandoned.
  7. PagesHTML: page name and arrows now, count if the owner lists pages. Figma: stop hiding Figma’s controls on test pages now; a live count later with the Embed API.
  8. ButtonsV3 caustic glass buttons everywhere in the tester UI. TaskPanel still uses the older GlassButton.
  9. Menu and minimiseIn A, remove Move panel and Minimise and keep Restart, Mute and End test behind the ⋯. Keep both in C, with text labels.
  10. Words“Share tab” is removed. Start test is the button. The fallback says “Record the Pocket tab”.
  11. The two-tab overlayDraw the same bar inside the site’s tab, so there is one design in both flows.
